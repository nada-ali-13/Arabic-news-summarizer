# إعداد وحدة استرجاع تقارير التدقيق

## 1. النطاق التشغيلي

تتيح خُلاصة البحث عن تقارير تدقيق منشورة باستخدام Google Fact Check Tools API، بصورة مستقلة عن تلخيص AraT5v2. وُثّق نجاح الوظيفتين في تشغيل خارجي على Google Colab بواسطة المطوّرة. لا تمثل وحدة التدقيق مصنفًا عامًا لصحة الأخبار؛ تُعرض تقييمات الجهات الأصلية وروابط تقاريرها دون تحويلها إلى أحكام مستقلة للنموذج.

مسار التشغيل المعتمد هو [Khulasa_Final_Demo.ipynb](../notebooks/Khulasa_Final_Demo.ipynb). يعتمد على `app.py` الحالي، ولا يستخدم واجهة Gradio التاريخية المضمّنة في دفتر سابق. لا يتضمن تدريبًا أو تنزيلًا للأوزان الخاصة. تفاصيل التثبيت العام في [README](../README.md).

## 2. إعداد Google Colab

يتطلب العرض الكامل جلسة نظيفة، ويفضّل T4 GPU، ونسخة مصرحًا بها من النموذج المضبوط وTokenizer. في واجهة Colab Secrets يُضاف `FACT_CHECK_API_KEY` ويُمنح الدفتر إذن قراءته. لا تُوضع قيمة المفتاح في الخلايا أو Git أو صور الشاشة أو عناوين الطلبات.

ينفّذ الدفتر النهائي الخطوات الآتية:

1. جلب المصدر من `feature/fact-checking` وتسجيل بصمة الإصدار؛ تُرفض التغييرات المحلية أو المصدر المختلف قبل التحديث.
2. تثبيت الاعتمادات، بما فيها Gradio 5.49.1، مع تقييد PyTorch بالإصدار المثبت أصلًا على Colab.
3. تعطيل TensorFlow وFlax قبل الاستيراد، وتفعيل Google فقط.
4. ربط Drive وقراءة السر دون عرضه.
5. إدخال مسار النموذج المصرح به بإدخال مخفي، وفحص ملفات الإعداد وTokenizer والأوزان وأجزاء التصدير عند وجودها.
6. تحميل النموذج مسبقًا في وضع العرض الكامل، ثم إطلاق `build_app(summarizer=summarizer)`.

المسار العام لخادم قائم داخل checkout مهيّأ هو:

```python
import os
from google.colab import userdata
os.environ['USE_TF'] = '0'
os.environ['USE_FLAX'] = '0'
os.environ['FACT_CHECK_API_KEY'] = userdata.get('FACT_CHECK_API_KEY')
os.environ['KHULASA_FACTCHECK_ENABLED'] = '1'
os.environ['KHULASA_GDELT_ENABLED'] = '0'
os.environ['KHULASA_NLI_ENABLED'] = '0'
# summarizer كائن محمّل مسبقًا من ملفات النموذج المصرح بها.
from app import build_app
build_app(summarizer=summarizer).launch(share=True)
```

الرابط الناتج عام ومؤقت، وليس استضافة دائمة. يجب عدم حفظ مخرجات تحتوي بيانات حساسة عند مشاركة الدفتر. عند تحديث المصدر بعد تحميل وحدات Python، تلزم إعادة تشغيل الجلسة لتجنب استخدام وحدات قديمة مخزنة في الذاكرة.

## 3. إعدادات التشغيل

| المتغير | القيمة الافتراضية أو الاستخدام |
|---|---|
| `FACT_CHECK_API_KEY` | سر مطلوب للبحث المباشر؛ غيابه لا يمنع التلخيص أو العرض المحفوظ |
| `ARABIC_SUMMARIZER_MODEL` | مجلد النموذج المضبوط المصرح به؛ غير منشور في المستودع |
| `KHULASA_FACTCHECK_ENABLED` | `1`؛ تعطيله بالقيمة `0` يترك التلخيص متاحًا |
| `KHULASA_GDELT_ENABLED` | `0`؛ لا تُرسل طلبات GDELT في التشغيل الافتراضي |
| `KHULASA_NLI_ENABLED` | `0`؛ لا يلزم Google ولا يُنزّل نموذج أثناء الطلب |
| `KHULASA_EVIDENCE_HOSTS` | قائمة مضيفين معتمدين يدويًا للنص الكامل؛ لا تلزم لمسار Google الافتراضي |

في الدفتر، `FULL_DEMO=True` يحمّل النموذج قبل الواجهة. القيمة `False` مخصصة لفحص الواجهة والتدقيق دون أوزان، ولا توفر تلخيصًا إنتاجيًا. اختبار التوليد الاصطناعي `RUN_SUMMARY_SMOKE` غير مفعّل افتراضيًا.

## 4. المعالجة والعرض

تستخرج `claims.py` حتى ثلاثة جمل خبرية أصلية بقواعد محدودة، وليست بنموذج استخراج متعلم. يبحث عميل Google لكل جملة عبر `claims:search` و`languageCode=ar`، حتى خمسة سجلات. تُحفظ حقول الادعاء والجهة والتقييم والرابط وتاريخ المراجعة والادعاء عند توفيرها.

تستخدم `evidence.py` تطبيعًا ومطابقة معجمية محافظة، مع فحص الأرقام والنفي وتكرار المصادر. لا تتحقق هذه القواعد بصورة شاملة من هويات الكيانات أو الزمن. تعرض الواجهة التقييم المنشور فقط عند وجود صلة كافية ورابط صالح. لا يُمرر الادعاء المراجَع نفسه إلى NLI بوصفه دليلًا على صحته.

في حالة ادعاء واحد مطابق، يظهر تقييم الناشر في بطاقة بارزة. في حالة عدة ادعاءات، يظهر ملخص واحد بأعداد المفحوص والمطابق، وتفاصيل مطوية بمعاينات قصيرة يمكن توسيعها. تبقى التقارير المطابقة ظاهرة رغم غياب تقارير للادعاءات الأخرى. عدم توافر تقارير مناسبة لا يثبت صحة الخبر أو خطأه، ولا ينتج حكمًا كليًا للمقال. يُهَرَّب النص الخارجي وتُفحص روابطه قبل العرض.

## 5. سجل العرض المحفوظ

يتضمن `fixtures/demo.json` سجلًا عامًا واحدًا:

| الحقل | القيمة |
|---|---|
| الادعاء | لقاحات كوفيد-19 تسببت بتفشي فيروس هانتا |
| الجهة | في ميزان فرانس برس |
| التقييم الأصلي | مضلّل |
| المصدر | https://factcheckarabic.afp.com/doc.afp.com.B3FY2T3 |
| تاريخ الاسترجاع | 2026-11-09، وفق سجل اختبار Colab الخارجي |

يظهر الوسم **وضع العرض — نتائج محفوظة وليست تحققًا مباشرًا**. لا يرسل هذا الوضع طلبات API ولا يتحقق من الإدخال الحالي، ولا ينفذ NLI. تاريخ الاسترجاع ليس تاريخ نشر التقرير؛ لم يُختلق تاريخ مراجعة غير متاح. قد تتغير نتائج البحث الحي لاحقًا وفق تغطية الخدمة.

## 6. الحصص والأعطال

تتضمن `http.py` مهلة طلب حتى 6 ثوانٍ، وحتى ثلاث محاولات للأخطاء المؤقتة، وbackoff مع `Retry-After`، ومنع التحويلات، وحد حجم JSON. التخزين المؤقت في الذاكرة مدته 15 دقيقة حتى 128 استعلامًا. حد Google المحلي محاولة كل ثانيتين لكل عملية؛ قد يؤدي الإرسال المتتابع إلى امتناع محلي بدل انتظار متراكم. ليس هذا محدد حصة مشتركًا بين عدة عمليات.

تُجدول عمليات البحث ضمن ميزانية 60 ثانية. لا تمثل الميزانية إلغاءً صارمًا لتحميل نموذج محلي أو كل عملية قراءة. الحصة المرصودة في حساب التشغيل كانت 300 طلب/دقيقة؛ لا تثبت حدًا يوميًا غير محدود أو تكلفة صفرية دائمة. لا تُطبع مفاتيح أو رسائل استجابة خام. قد تتوقف النتائج الحية بسبب المصادقة أو الشبكة أو نفاد الحصة، دون تعطيل التلخيص.

## 7. المكونات الاختيارية

GDELT يكتشف تغطية إخبارية، ولا يوفر حكمًا على صحتها. أعاد اختبار Colab الخارجي 429 مع طلب فصل الطلبات بخمس ثوانٍ؛ يفرض العميل الحالي ست ثوانٍ ويظل معطّلًا افتراضيًا. لا تُستخدم العناوين وحدها دليلًا حاسمًا، ويخضع استخراج النصوص لحماية SSRF الأصلية.

نموذج NLI الاختياري هو `MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli`. وثّق فحص خارجي توافره بترخيص MIT وأوزان safetensors، وتحميله على CPU، وخرائط `0: entailment` و`1: neutral` و`2: contradiction`. أُجري اختبار من ثلاثة أمثلة عربية، وليس تقويمًا إنتاجيًا لصحة الأخبار. تفاصيل الأدلة في [تقرير التحقق](FACTCHECK_VALIDATION.md).

يعتمد محمّل NLI على ملفات محلية مجهّزة مسبقًا وCPU، ويعيد استخدام النموذج دون تخصيص GPU، ويفشل تحفظيًا إذا تعذر التحميل أو تعريف التسميات. لا تُجرى تنزيلات أثناء التحقق. دفعة الاستدلال 1 وحد التسلسل 384؛ الذاكرة والكمون غير مقاسين في بيئة التشغيل النهائية. لا يلزم تفعيله للوظائف الافتراضية.
